# Design preferences

These are the author's preferences, not universal design principles. Follow project-specific design rules and the user's requirements when they differ. Ask before changing an established design policy.

## Core preferences

- Favor simple, clean, minimal interfaces with the polish of a native product.
- Use interactive visuals when they improve understanding. Humor and playful styles can fit an appropriate audience and context.
- Keep designs light and simple; avoid arbitrary gradients, shadows, and decorative clutter.
- Use as shallow a hierarchy as possible.
- Minimize peripheral text and redundant labels. Avoid explanatory text between nested controls when the interface already conveys the relationship.
- Avoid oversized hero sections and motivational titles that convey no useful information.
- Make controls intuitive. For complex interactions, prefer concise contextual help or a brief optional tutorial over a permanent inventory of every control.
- For TUIs, provide scrolling alternatives that work on keyboards without dedicated Page Up and Page Down keys. Check terminal compatibility before choosing shortcuts.
- Avoid small, low-contrast subtitles that merely restate a heading. Put the next meaningful information in the body. When a diagram or table needs a caption, use as few words as clarity allows.
